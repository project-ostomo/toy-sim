# Workspace appearance audit

Inspected live Figma images and software screenshots on 2026-09-24. This is an appearance audit; no product source was changed. Iosevka Charon is an intentional user requirement. Different example names and physical quantities are not visual defects.

## Highest priority findings

1. **The gallery does not verify most actual workspace compositions.** Only `shell` and `settings` call `panels::draw`; navigation, map, cargo, consumables, storage, hangar and chat call individual content functions directly into the entire canvas (`crates/osg-client/src/ui/shell/tests/workspace.rs:224`). Their screenshots omit the surrounding window, launcher, overview and status bar. Figma consistently depicts compact floating windows within that shell. This explains the huge blank areas and full-width separators in the gallery, but does not prove that runtime windows are absent. Generate these states through the real shell before approving appearance.

2. **The map has a different layout in actual source.** [Figma 7:262](https://www.figma.com/design/kvxDvZDyEbkfgU25IDzyyd?node-id=7-262) has a 1200×800 window with three columns: preferences and star list, map, selected destination and route. `workspace-map-1600x900.png` stacks preferences above a very wide map and route information below. `crates/osg-client/src/ui/shell/map.rs:145` confirms this is the actual implementation: search is above the canvas and selected-system/route information is in a bottom panel. It also lacks the visible persistent star-system list and Bloc/Polity/Your standing segmented control. Restore the three-column desktop layout; define an explicit compact arrangement rather than allowing the footer to consume most of a small map.

3. **Shared window chrome and spacing differ visibly.** [Figma shell 2:2](https://www.figma.com/design/kvxDvZDyEbkfgU25IDzyyd?node-id=2-2) uses left-aligned small titles in approximately 24px bars with small close marks. `workspace-shell-1600x900.png` shows centered titles, approximately 32px bars, much larger close marks and resize corners. The selected-item bottom weapons status is visibly clipped at both 1600×900 and 900×650. `crates/osg-ui/src/desktop.rs:190` relies on the native egui window title layout; `crates/osg-ui/src/theme.rs:32` sets 8px vertical item gaps, 6px vertical button padding and 28px minimum controls. `crates/osg-client/src/ui/shell/panels.rs:238` caps selected-content scrolling against the whole window height instead of the available content height. Match title metrics and compact control spacing, and ensure all selected-item status content fits or scrolls visibly.

4. **Compact shell navigation is inaccessible.** `workspace-shell-900x650.png` visibly cuts off the launcher below the market area; the settings icon is absent. The rail keeps its desktop sequence and fixed spacing while the screen height shrinks (`crates/osg-client/src/ui/shell/panels.rs:20`, `crates/osg-ui/src/desktop.rs:312`). Provide scrolling or compact spacing with settings kept accessible.

5. **Quantity dialog bypasses shared chrome.** [Figma 6:708](https://www.figma.com/design/kvxDvZDyEbkfgU25IDzyyd?node-id=6-708) has a compact approximately 300×170 dialog, small left-aligned title and solid surface. `workspace-quantity-900x650.png` shows an oversized centered heading and a much taller title region, with underlying cargo visible through the surface. `crates/osg-client/src/ui/shell/cargo.rs:341` constructs a raw `egui::Window` with a plain string title and default placement. Use the same compact dialog frame/title styling as the other windows. The apparent transparency should be verified after egui animations settle before changing runtime opacity.

## Color and screenshot limitations

The shared palette already defines cyan, green, mint, amber and red (`crates/osg-ui/src/desktop.rs:6`). The shell sample uses one neutral station, and the map has no sovereignties or planned route. Their missing green/red/amber information is partly a fixture issue. The shell shot also looks dimmer than Figma; only five frames are rendered and window animations may still be active. Verify stable frames before attributing that dimming to palette constants. Generic widget styling and desktop surfaces are separate definitions and should be reconciled where they cause visible discrepancies.

The renderer fills uncovered pixels with gray RGB(15,15,15), and it deliberately has no 3D scene (`crates/osg-client/src/ui/shell/tests/software.rs:44`). Figma uses a dark placeholder scene too. Neither the gray gallery backdrop nor absent world rendering is evidence of a runtime scene defect. Figma images here are desktop references; 900×650 was inspected for clipping and usability, not pixel parity with an unavailable compact design.

Evidence files are under `target/ui-gallery/workspace-{shell,settings,navigation,map,cargo,consumables,storage,hangar,quantity,chat}-{1600x900,900x650}.png`. First repair the gallery composition and populate representative states, then compare shared chrome, map composition, and screen-specific details against the live frames.

## Corrections after the audit

Workspace captures now use the actual shell and floating windows for every variant, with animation disabled and populated cargo, kits, route/fuel state, hangar ships, overview standings and polity colors. The root task corrected shared window chrome and palette. Selected-item content uses its available scroll height; the launcher scrolls with settings pinned at the bottom. The quantity dialog uses shared compact chrome and physical resource masses.

The map now uses desktop columns for preferences/star list, canvas and route details, with working Bloc/Polity/Your standing coloring. Compact windows collapse preferences and place route details below the canvas. Interface settings and Local chat use sidebar composition with their existing functional controls. The current Figma Graphics, Controls, Notifications and direct-message workflows still require additional functionality; the styling changes here do not implement those workflows.

The first regenerated workspace gallery test passed and its shell, cargo, quantity and map images were inspected. That inspection exposed map route controls expanding into the canvas; controls now wrap and the details pane clips to its own bounds. Compact shell inspection confirmed settings remains accessible and the selected-item bottom status remains visible. Final verification is recorded in the parent task.
